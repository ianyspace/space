数据库索引为什么几乎都用 B+ 树？很多人背过结论，却说不清插入时节点到底怎么分裂、删除时又怎么合并。

## 一、为什么需要 B+ 树

如果把数据放进内存里查找，红黑树、跳表都很好用，$O(\log n)$ 的复杂度已经足够快。但数据库的数据在**磁盘**上，真正的瓶颈不是比较次数，而是**磁盘 I/O 次数**。

一次磁盘读取的单位是「页」（page，常见 4 KB 或 16 KB）。我们希望：

1. **一次 I/O 尽量多读一些有用的键**，而不是只读到两三个；
2. **树要「矮胖」**，因为树高就等于最坏情况下的 I/O 次数。

二叉树每个节点只有 2 个孩子，100 万条数据树高约 20，意味着最多 20 次随机 I/O。B+ 树是多路平衡树：一个节点可以存几百个键，同样 100 万条数据树高只要 3～4 层，2～3 次 I/O 就能命中。这就是它存在的全部理由。

> 一句话：**用节点内的有序数组，把树的「宽度」换成「高度」的降低。**

## 二、B 树 vs B+ 树

B 树（B-Tree）和 B+ 树（B+Tree）最常被拿来对比，差别集中在两点：**数据放在哪、叶子之间是否相连**。

| 维度 | B 树 | B+ 树 |
| --- | --- | --- |
| 数据存放位置 | 每个节点（内部 + 叶子）都存数据 | **只有叶子节点存数据**，内部节点只存分隔键 |
| 键是否重复 | 每个键只出现一次 | 内部节点的键是叶子键的**副本**（用于导航） |
| 叶子节点 | 相互独立 | 用**双向/单向链表**串成一串 |
| 单节点出度 | 相对小（要存数据） | 更大（只存键），树更矮 |
| 范围查询 | 需要中序遍历，来回跳 | 定位左端点后**顺着叶子链表扫**即可 |
| 典型用途 | 文件系统、部分内存结构 | **数据库索引**（MySQL InnoDB 等） |

范围查询是 B+ 树的关键优势。执行 `WHERE id BETWEEN 100 AND 200` 时，B+ 树先 $O(\log n)$ 定位到 100 所在叶子，然后沿着叶子链表顺序读取——这正是磁盘最喜欢的**顺序 I/O**。

## 三、B+ 树的定义与术语

先约定几个词，后面的演示都按这个定义来：

- **阶（order，记作 $m$）**：一个节点最多能有 $m$ 个孩子，也就是最多 $m-1$ 个键；
- **键数上限**：$m-1$；
- **键数下限**：$\lceil m/2 \rceil - 1$（**根节点除外**，根可以有 0 个键）；
- **叶子**：存放真实键，且所有叶子在**同一层**，从左到右用指针连成有序链表；
- **内部节点**：只存放分隔键和指向孩子的指针。

B+ 树的核心不变式，可以浓缩成四条：

1. 节点内键**从小到大有序**；
2. 对内部节点第 $i$ 个键 $k_i$：左子树的所有键 $< k_i \le$ 右子树的所有键；
3. 所有叶子在**同一深度**（因此树是绝对平衡的）；
4. 除根外，任何节点的键数都在 $[\lceil m/2 \rceil - 1,\ m-1]$ 之间。

## 四、查找：自顶向下，一层一次 I/O

查找的过程非常直白：

1. 从根节点开始，在节点内用**二分查找**找到第一个大于目标键的位置 $i$；
2. 如果目标键 $\ge$ 第 $i-1$ 个键，就走第 $i$ 个孩子（指针数组比键数组多一个）；
3. 重复直到抵达叶子节点，再看叶子里有没有这个键。

```js
function search(node, key) {
  if (node.leaf) {
    return node.keys.includes(key) ? key : null; // 叶子才存真实数据
  }
  let i = 0;
  while (i < node.keys.length && key >= node.keys[i]) i++; // 选第 i 个孩子
  return search(node.children[i], key);
}
```

注意：**即使内部节点里出现了目标键，也不能在这里停下**，因为内部节点的键只是分隔用的副本，真实数据只在叶子里。演示里点「查找」，会看到蓝色高亮沿着一条路径一路走到叶子。

## 五、插入：先落叶子，溢出就分裂

插入分两步：**向下找位置**，**向上处理溢出**。

### 5.1 向下定位

和查找一样，沿着分隔键一路走到目标叶子，把键插入到有序位置。

### 5.2 溢出就分裂（split）

如果插入后叶子键数达到 $m$（即超过上限 $m-1$），就把这个叶子**一分为二**：

- 左半留下前 $\lceil m/2 \rceil$ 个键；
- 右半拿走剩下的键，单独成为一个新叶子；
- 把右半的**第一个键复制**一份，插入到父节点中作为新的分隔键。

关键细节：叶子分裂时是「**复制**」上去——因为数据必须留在叶子里，父节点只是多了一个导航用的副本。

### 5.3 分裂向上传播

父节点接收新分隔键后也可能溢出，此时对内部节点做同样的分裂，但规则略有不同：

- 内部节点分裂时，中间那个键是**移动**到父节点，而不是复制（它本来就不是数据，只是分隔符）；
- 如果一直分裂到根节点，就创建一个新的根节点，树高 +1。B+ 树就是这样「长高」的，而且**永远是从根部长高**，所以所有叶子始终在同一层。

```js
// 返回 { promote, right } 表示需要向上插入分隔键 promote 和新节点 right
function insert(node, key, order) {
  const maxKeys = order - 1;

  if (node.leaf) {
    const at = lowerBound(node.keys, key);      // 有序插入位置
    if (node.keys[at] === key) return null;     // 一般不允许重复键
    node.keys.splice(at, 0, key);
    if (node.keys.length <= maxKeys) return null;

    const mid = Math.ceil(order / 2);           // 叶子：右半的第一个键「复制」上去
    const right = { keys: node.keys.splice(mid), children: [], leaf: true };
    return { promote: right.keys[0], right };
  }

  let i = 0;
  while (i < node.keys.length && key >= node.keys[i]) i++;
  const res = insert(node.children[i], key, order);
  if (!res) return null;

  node.keys.splice(i, 0, res.promote);          // 分隔键插入父节点
  node.children.splice(i + 1, 0, res.right);
  if (node.keys.length <= maxKeys) return null;

  const mid = Math.floor(order / 2);            // 内部节点：中间键「移动」上去
  const promote = node.keys[mid];
  const right = {
    keys: node.keys.slice(mid + 1),
    children: node.children.slice(mid + 1),
    leaf: false,
  };
  node.keys = node.keys.slice(0, mid);
  node.children = node.children.slice(0, mid + 1);
  return { promote, right };
}
```

## 六、删除：下溢就借位或合并

删除比插入要麻烦一点，因为它要维持**键数下限**。流程是「先删，后补救」。

### 6.1 先在叶子里删掉

定位到叶子，把键移除。如果删除后键数仍然 $\ge \lceil m/2 \rceil - 1$，那就结束了。

### 6.2 下溢（underflow）

如果删除后键数低于下限，就发生了**下溢**，需要向兄弟节点求助，优先级是：

1. **向兄弟借（borrow）**：如果左（或右）兄弟的键数大于下限，就「借」一个键过来，并**更新父节点里的分隔键**，保证「左子树全部小于分隔键」这一不变式仍然成立；
2. **与兄弟合并（merge）**：如果两个兄弟都刚好到下限，谁也借不出来，就把两者合并成一个节点，同时把父节点中对应的分隔键删掉；
3. **向上传播**：合并会让父节点少一个键，父节点可能也下溢，于是递归地向上借位/合并；
4. **根收缩**：如果根节点最后没有键了，就让它唯一的孩子成为新根，树高 -1。

```js
function fixUnderflow(parent, i, order) {
  const minKeys = Math.ceil(order / 2) - 1;
  const child = parent.children[i];
  const left = parent.children[i - 1];
  const right = parent.children[i + 1];

  // 1) 向左兄弟借
  if (left && left.keys.length > minKeys) {
    if (child.leaf) {
      child.keys.unshift(left.keys.pop());
      parent.keys[i - 1] = child.keys[0];        // 更新分隔键
    } else {
      child.keys.unshift(parent.keys[i - 1]);
      child.children.unshift(left.children.pop());
      parent.keys[i - 1] = left.keys.pop();
    }
    return false;
  }

  // 2) 向右兄弟借
  if (right && right.keys.length > minKeys) {
    if (child.leaf) {
      child.keys.push(right.keys.shift());
      parent.keys[i] = right.keys[0];
    } else {
      child.keys.push(parent.keys[i]);
      child.children.push(right.children.shift());
      parent.keys[i] = right.keys.shift();
    }
    return false;
  }

  // 3) 都借不到 —— 合并
  if (left) {
    left.keys.push(...(child.leaf ? [] : [parent.keys[i - 1]]), ...child.keys);
    if (!child.leaf) left.children.push(...child.children);
    parent.keys.splice(i - 1, 1);
    parent.children.splice(i, 1);
  } else {
    child.keys.push(...(child.leaf ? [] : [parent.keys[i]]), ...right.keys);
    if (!child.leaf) child.children.push(...right.children);
    parent.keys.splice(i, 1);
    parent.children.splice(i + 1, 1);
  }
  return parent.keys.length < minKeys; // 父节点可能也要继续处理
}
```

在演示里删除几个键，就能看到「借位」与「合并」两种不同的补救方式，以及分隔键是如何被同步更新的。

## 七、复杂度与树高

设阶为 $m$、总键数为 $n$。

- **树高**：每个内部节点至少有 $\lceil m/2 \rceil$ 个孩子，所以高度满足

  $$
  h \le \log_{\lceil m/2 \rceil} n
  $$

- **查找**：$O(\log_m n)$ 次节点访问，每次节点内二分是 $O(\log m)$；
- **插入 / 删除**：同样是 $O(\log_m n)$，且分裂/合并只在一条根到叶的路径上发生；
- **范围查询**：$O(\log_m n + k)$，其中 $k$ 是结果条数，叶子链表让它退化成顺序扫描。

以 $m = 1000$ 为例：一层能放下约 1000 个指针，三层就能寻址 $10^9$（十亿）量级的数据，而根节点通常还会常驻内存——**真正打到磁盘的 I/O 往往只有 1～2 次**。

## 八、为什么数据库选了它

- **矮**：出度大 → 树高低 → I/O 少；
- **叶子成链**：范围扫描、`ORDER BY`、分页都能顺序读；
- **节点对齐页**：一个节点正好放进一个磁盘页，读一个节点 = 一次 I/O；
- **绝对平衡**：所有查询路径长度相同，性能没有抖动；
- **插入删除是局部操作**：只影响一条路径，天然适合并发控制（InnoDB 用 latch 精细控制）。

MySQL InnoDB 的聚簇索引就是一棵 B+ 树：叶子节点存整行数据，主键有序；二级索引的叶子存主键值，需要「回表」。理解 B+ 树的分裂与合并，也就理解了为什么主键建议**自增且单调**——随机主键会导致频繁的页分裂和碎片。

## 九、小结

| 操作 | 一句话记忆 |
| --- | --- |
| 查找 | 内部节点只导航，真实数据在叶子 |
| 插入 | 叶子先插，溢出就分裂；叶子**复制**、内部**移动**，一路向上传 |
| 删除 | 叶子先删，下溢就**先借后合**，一路向上传 |
| 长高 / 变矮 | 只发生在根节点，所以永远绝对平衡 |

最后再玩一遍完整过程，这次留意三件事：**分隔键什么时候被更新**、**新节点是在哪一步出现的**、**树高在哪一步变化**。
